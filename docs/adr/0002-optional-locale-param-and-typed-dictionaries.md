# Optional locale route param and our own typed dictionaries over Paraglide

The site is in English, French and Arabic. English keeps its addresses (`/learn`), the others are prefixed (`/fr/learn`), and every page is prerendered in each. TanStack's own guide offers two ways: Paraglide JS with URL rewriting, or the router's optional path param `{-$locale}` with translations we manage ourselves. We take the second. Our text is nested typed objects with lists, lesson cases keyed by id and functions for plurals, shared between a method's lessons and its solver hints; Paraglide wants flat message keys in JSON compiled to one function each, which would mean rewriting every text file and every `m.…` read, and by default each compiled message carries all languages, so an English reader would download the Arabic lessons (splitting by language is still experimental there). Its rewriting also needs a per-request language store on the server, where a route param is in the router's state and so is safe to prerender by construction. With the param, each language is one file typed as `Messages` (`typeof en`): `tsc` fails on a missing key, a language is one dynamic import loaded by the root route, and `useM()` replaces the old `m` import with one line per component. The accepted costs: links are written `to="/{-$locale}/…"`, the pages to prerender are listed in `src/lib/pages.ts` because the crawler cannot see the closed language menu, the client entry (`src/client.tsx`) fetches the page's language before hydration, and shape rules that types cannot express (list lengths, case ids, untouched notation) are held by `src/i18n/locales.test.ts`.
